# AI Knowledge Task Hub 设计审查报告

审查日期：2026-06-01

审查方式：使用 Playwright 打开本地 Next.js 应用，覆盖桌面端 1440x900 与移动端 390x844，页面包括首页、笔记、任务、项目、AI 助手、AI 配置。

截图目录：`D:\project\codex\knowledge\.gstack\design-reports\design-audit-local-20260601\screenshots`

## 总体结论

这是一个明确偏工具型的 App UI，而不是营销落地页。当前视觉方向有辨识度：纸质底纹、粗黑描边、荧光绿标签、硬阴影，让产品看起来像“个人知识任务工作台”。问题也很集中：桌面端可用但偏重，移动端存在明显横向裁切和导航溢出；大量卡片、粗边框和强色标签让用户很难快速判断“现在应该做什么”。

设计评分：C+

AI 痕迹评分：B-

用户好感度：56/100

主要扣分来自移动端溢出、过重的卡片化布局、过强的标题和状态装饰、筛选区密度过高。

## 主要设计缺陷

### 1. 移动端导航横向裁切

证据：

- `screenshots/home-mobile.png`
- `screenshots/tasks-mobile.png`
- `screenshots/settings-ai-mobile.png`

我注意到顶部移动导航只露出前几个入口，右侧的 AI 相关入口被截断，只剩半个按钮。用户需要猜测是否能横向滑动，且当前页状态不够明显。

影响：高。移动端第一屏会让用户感觉界面没有适配手机。

建议：把移动导航改成可横滑的分段导航，并保留左右内边距和滚动阴影；或者改成“当前模块 + 菜单”结构。当前页需要稳定高亮，避免所有按钮看起来同等重要。

### 2. 移动端主容器和卡片存在横向溢出

证据：

- `screenshots/home-mobile.png`
- `screenshots/notes-mobile.png`
- `screenshots/tasks-mobile.png`

我注意到多个卡片的正文在右侧被切掉，例如首页开发流程、笔记列表摘要、任务卡片摘要。布局像是桌面卡片直接压缩到手机宽度，而不是重新组织。

影响：高。正文被裁切会直接影响阅读和信任。

建议：检查所有固定宽度、最小宽度和网格列设置；移动端统一使用单列流式布局，卡片内长文本设置 `line-clamp` 或自然换行，避免内容宽度超过父容器。

### 3. 卡片和阴影过多，工具界面显得沉重

证据：

- `screenshots/home-desktop.png`
- `screenshots/tasks-desktop.png`
- `screenshots/settings-ai-desktop.png`

我注意到几乎每个区域都是粗边框卡片加硬阴影：页面容器、搜索框、说明框、列表项、预设项、按钮都在争夺同一个视觉层级。

影响：中高。桌面端不是不能用，但长时间使用会有视觉疲劳。

建议：保留“纸质工作台”的品牌感，但只让关键对象使用强描边。普通分组改成浅背景或细分隔线；列表项减少阴影，按钮保留明确边界即可。

### 4. 页面标题过大，挤压真正工作区

证据：

- `screenshots/tasks-desktop.png`
- `screenshots/projects-desktop.png`
- `screenshots/settings-ai-mobile.png`

我注意到二级页面仍使用接近英雄区的标题尺度。对工具型页面来说，用户更关心筛选、列表、表单和状态，而不是每次都重新阅读大标题。

影响：中。桌面端浪费首屏，移动端首屏尤其明显。

建议：将二级页面标题缩小，形成紧凑页头；把状态、主操作按钮、关键筛选入口整合在页头或工具栏中。

### 5. 筛选区在移动端过密，扫描成本高

证据：

- `screenshots/tasks-mobile.png`
- `screenshots/notes-mobile.png`

我注意到任务页筛选项包括项目、状态、优先级、截止日期、标签，全部展开后在移动端占据大量首屏空间，且每组按钮视觉权重接近。

影响：中高。任务管理页的核心目标是处理任务，但用户先被筛选按钮淹没。

建议：桌面端可以保留展开筛选；移动端改成筛选抽屉、折叠面板或“筛选按钮 + 当前条件摘要”。高频筛选保留在外层，低频筛选收起。

### 6. 色彩语义不够克制

证据：

- `screenshots/home-desktop.png`
- `screenshots/tasks-desktop.png`

我注意到荧光绿既表示阶段标签，也表示选中态、优先级、AI 标签和状态标识；橙色也同时用于项目标签、开放状态和强调边条。

影响：中。颜色没有稳定语义，用户需要读文字而不是凭颜色识别状态。

建议：建立语义色：一个主强调色、一个危险/逾期色、一个完成色、一个中性色。标签颜色可以保留多彩，但操作状态和业务状态应分开。

### 7. AI 配置页表单优先级偏后

证据：

- `screenshots/settings-ai-desktop.png`
- `screenshots/settings-ai-mobile.png`

我注意到预设卡片占据了表单前的大量空间，移动端用户要滚动很久才能看到真正需要填写的 Base URL、Model、API Key。

影响：中。配置页的用户目标是完成配置和测试连接，预设只是辅助。

建议：把 Provider Presets 改成横向选项卡、下拉模板或紧凑按钮组；把 Mode、Base URL、Model、API Key 和测试结果放到更靠前的位置。

### 8. 内容摘要过长，列表扫描效率低

证据：

- `screenshots/home-mobile.png`
- `screenshots/notes-mobile.png`
- `screenshots/tasks-desktop.png`

我注意到笔记和任务卡片里正文摘要很长，移动端形成大段灰字。列表页应该帮助用户快速判断“这是什么、是否需要处理、下一步是什么”。

影响：中。

建议：列表卡片只保留标题、日期、项目/标签、状态、两行摘要和一个主操作。长内容进入详情页，列表中使用渐隐或截断。

### 9. 页面状态文案削弱信任

证据：

- 多个桌面截图页头显示 `SKELETON READY`、`DB: OFFLINE`

我注意到页面说明写着数据来自 PostgreSQL，但页头状态又写 DB: OFFLINE。即使这是开发状态，也会让用户困惑：到底数据是否真实？

影响：中。

建议：开发态信息不要放在用户主界面里。若必须保留，改成只在开发环境显示的窄状态条；生产/演示界面应展示真实连接状态或移除。

### 10. 资源 404 需要排查

证据：

- 浏览器控制台在多个页面捕获到 `Failed to load resource: the server responded with a status of 404 (Not Found)`

影响：低到中。它不一定影响视觉，但会污染调试信号，可能是 favicon 或静态资源缺失。

建议：定位缺失资源路径，补齐 favicon、manifest 或相关静态文件。

## 快速修复项

1. 移动端顶部导航增加 `overflow-x: auto`、滚动内边距和当前项高亮，避免最后几个入口被裁掉。
2. 给列表摘要统一两到三行截断，移动端先保证不横向溢出。
3. 减少普通卡片硬阴影，只保留页面容器或关键操作的强调阴影。
4. 将二级页面 H1 缩小一档，移动端进一步缩小。
5. 将任务页低频筛选项折叠，移动端只展示“筛选”和当前条件摘要。

## 中长期完善方向

1. 建立设计令牌：颜色、字体、边框、阴影、间距都应有命名变量，避免每个组件各自发挥。
2. 明确 App UI 信息架构：页头用于定位和主操作，左侧/顶部导航用于模块切换，主区域用于列表或表单，辅助说明不要抢占核心工作区。
3. 移动端单独设计任务流：不是把桌面端压窄，而是重新排序“标题、主操作、筛选、列表、详情入口”。
4. 建立组件层级：按钮、徽章、卡片、面板、搜索框分别有不同视觉权重，不要都用同一套粗描边和硬阴影。
5. 为 AI 配置页增加结果反馈区：测试连接后显示成功、失败原因、下一步处理，而不是只有按钮。
