# 前端优化建议补充

来源报告：[design-audit-local.md](./design-audit-local.md)

生成日期：2026-06-01

适用项目：AI Knowledge Task Hub

技术栈：Next.js、React、TypeScript、Tailwind CSS。Next.js 是基于 React 的全栈框架，适合把页面渲染、路由和 API 放在同一个项目里管理；Tailwind CSS 是原子化 CSS 框架，通过组合类名快速构建界面样式。

- P7 微交互：已加入 150ms 左右的颜色、边框、阴影状态过渡，并尊重 `prefers-reduced-motion`。
- 静态资源 404：已新增 `src/app/icon.svg`，首页控制台 404 已消失。

已验证：

- `npm.cmd run lint` 通过。
- Playwright 检查 `/`、`/notes`、`/tasks`、`/projects`、`/ai`、`/settings/ai` 在 390px 移动端均无横向溢出。

待实施：

- 375px、414px、横屏和平板断点还需要补充截图回归。
- 筛选折叠目前是原生 `details`，后续可升级为带“清除全部”和已选数量的筛选抽屉。
- 当前只做浅色主题；暗色模式仍不建议马上做，需等设计令牌继续稳定。

- 项目详情页、编辑页、表单页还未做同等深度的视觉减重和移动端专项检查。

## 设计定位

当前界面应继续按“个人知识任务工作台”处理，而不是营销页。建议保留纸质工作台、粗描边、荧光状态标签这些识别点，但把视觉重量从“所有元素都很重”调整为“关键操作和当前状态更重，普通内容更轻”。

推荐方向：轻量新粗野主义 (Neo-Brutalism Lite)。新粗野主义是一种强调强边框、高对比和直接表达的界面风格；这里的 Lite 表示只保留识别度，不把每个组件都做成重边框和硬阴影。

## 前端优先级路线

### P0：先修移动端可用性

目标：消除横向裁切和横向滚动，让 390px 宽度手机可正常完成浏览、筛选、进入详情和配置 AI。

关联问题：

- 移动端导航横向裁切
- 移动端主容器和卡片横向溢出
- 任务筛选区在移动端过密

建议改动：

1. `src/components/layout/sidebar-nav.tsx`
   - 紧凑导航保留 `overflow-x-auto`，但增加 `max-w-full`、`scroll-px-4`、`[scrollbar-width:none]`，并给导航容器加左右渐隐提示。
   - 链接增加当前页选中态。当前页状态 (Selected State) 是指用户能从视觉上知道自己处在哪个模块，常用 `aria-current="page"` 和更强的背景/边框表达。
   - 每个移动端导航项触控面积不低于 44x44px。触控目标 (Touch Target) 是手指可以稳定点击的区域，过小会造成误触。

2. `src/components/layout/app-shell.tsx`
   - 外层内容容器保留 `min-w-0`，主面板增加 `max-w-full`。
   - 移动端主面板建议从 `p-5` 降到 `p-4`，减少内容被边框和内边距挤压。
   - 页面容器不要隐藏真实溢出问题；当前 `overflow-hidden` 会把右侧内容裁掉，建议只在明确需要裁剪视觉装饰时使用。

3. `src/components/tasks/task-card.tsx`、`src/components/notes/note-card.tsx`
   - 所有卡片根元素增加 `min-w-0`。
   - 标题、摘要、标签容器统一加 `min-w-0`，避免 flex/grid 子项撑破父容器。
   - 摘要统一使用两到三行截断，并提供详情入口承接完整内容。

验收标准：

- 390x844、375x667、414x896 三个视口没有横向滚动条。
- 顶部导航可以访问所有模块，当前页明显高亮。
- 首页、笔记、任务、项目、AI 配置页正文不再被右侧裁切。

### P1：建立设计令牌和层级规则

目标：把颜色、阴影、边框、圆角和间距收敛成稳定系统，减少每个组件各自加重的情况。

设计令牌 (Design Tokens) 是把颜色、字号、阴影、间距等设计决策命名成变量的做法。这样组件不用硬编码视觉值，后续统一改风格也更可控。

关联文件：

- `tailwind.config.ts`
- `src/app/globals.css`
- `src/components/ui/module-panel.tsx`
- `src/components/ui/page-header.tsx`

建议令牌：

| 类型 | 当前问题 | 建议 |
| --- | --- | --- |
| 颜色 | `accent` 同时表示选中、AI、优先级和阶段 | 拆成 `primary`、`selected`、`success`、`warning`、`danger`、`tagAi` |
| 阴影 | `shadow-panel` 用在几乎所有元素 | 增加 `shadow-raised`、`shadow-soft`、`shadow-none` 三档 |
| 边框 | 普通内容和关键操作都用 2px 黑边 | 面板 2px，普通卡片 1px，输入框聚焦 2px |
| 间距 | 移动端内容被挤压，桌面端首屏偏松散 | 建议使用 4/8px 间距体系：4、8、12、16、24、32、48 |
| 圆角 | 所有元素都接近同一圆角 | 卡片 8px，按钮 6px，标签 4px |

组件层级建议：

1. 页面容器：保留粗边框和最强阴影，用作品牌框架。
2. 功能面板：保留边框，阴影降一级。
3. 列表卡片：边框降到 1px 或保留 2px 但取消硬阴影。
4. 标签和状态：只用颜色和文字，不再叠加强阴影。
5. 按钮：主按钮保留高对比，次按钮只保留边框。

验收标准：

- 全局强硬阴影使用量减少至少 50%。
- 普通列表卡片不再和主操作按钮同等抢眼。
- 颜色语义稳定：用户看到颜色可以大致判断是选中、完成、警告还是危险。

### P2：压缩页头，把首屏还给工作流

目标：工具型页面首屏优先显示用户要处理的对象，而不是重复展示大标题和开发状态。

关联文件：

- `src/components/ui/page-header.tsx`

建议改动：

1. 首页可以保留较强标题，二级页面标题降低到 `text-3xl md:text-5xl` 或更小。
2. 移除用户界面里的 `SKELETON READY`、`DB: OFFLINE`；如果确实需要开发态，可放到开发环境专用 Debug 条。
3. 页头增加可选 `actions` 插槽，用来放“新建任务”“新建笔记”“测试连接”等主操作。
4. 描述文案限制为一行到两行，详细说明放到帮助面板或空状态中。

验收标准：

- 任务页首屏能同时看到标题、主操作、核心筛选摘要和第一条任务。
- AI 配置页首屏能看到至少 Mode、Label、Base URL 或主要配置入口。
- 用户态页面不再出现内部开发状态文案。

### P3：重构筛选区为“高频外露、低频折叠”

目标：任务页和笔记页的筛选不再压过内容列表。

渐进披露 (Progressive Disclosure) 是把低频或复杂选项先收起，只在用户需要时展开。它能降低首屏认知负担，尤其适合移动端筛选和高级设置。

建议结构：

- 桌面端：保留横向筛选栏，但每组筛选视觉权重降低。
- 移动端：只显示“筛选”按钮、当前条件摘要和清除入口。
- 展开方式：用抽屉、折叠面板或独立筛选页，避免把所有按钮堆在首屏。

建议新增或改造组件：

- `src/components/ui/filter-rail.tsx`
  - 增加 `compact` 模式。
  - 支持 `activeCount`，显示“已选 3 项”。
  - 支持 `onClear` 或清除链接。

验收标准：

- 任务页移动端筛选区域高度不超过首屏的 25%。
- 已启用筛选条件能一眼看到。
- 清除筛选入口始终可见。

### P4：优化列表卡片的信息架构

目标：让笔记和任务列表更像工作台列表，而不是长文章卡片集合。

建议任务卡片顺序：

1. 状态和优先级
2. 标题
3. 项目、截止日期、更新时间
4. 两行摘要
5. 标签
6. 主操作

建议笔记卡片顺序：

1. 标题
2. 更新时间
3. 两到三行摘要
4. 标签
5. 查看入口

具体建议：

- `TaskCard` 当前已有 `line-clamp-2`，方向正确；继续补 `min-w-0` 和更明确的状态语义。
- `NoteCard` 当前使用 `max-h-36 overflow-hidden`，建议改为 `line-clamp-3`，否则会出现被硬裁切但没有省略语义的问题。
- “查看详情”在任务卡片中是文本链接，移动端触控面积偏小；建议改为次级按钮样式或增加内边距。

验收标准：

- 列表每张卡片可以在 2 秒内扫出标题、状态、是否需要处理。
- 摘要不会撑破卡片，也不会形成大段灰字。
- 所有详情入口触控区域至少 44px 高。

### P5：AI 配置页改成“配置优先”

目标：用户进入 AI 配置页后先完成配置和测试，而不是先阅读六张预设卡。

关联文件：

- `src/components/ai/ai-provider-settings.tsx`

建议布局：

1. 顶部：Mode、Provider preset 紧凑选择器、Label。
2. 中部：Base URL、Model、API Style、API Key。
3. 底部：保存、测试连接、测试结果。
4. 次要区域：预设说明折叠展示。

表单反馈建议：

- 对 Base URL 和 Model 做失焦校验。失焦校验 (Validation on Blur) 是用户离开输入框后再提示错误，避免输入过程中不断打断。
- 错误提示放在字段下方，不只放在表单底部。
- 测试连接时按钮进入加载态，并保留当前结果区域。
- 结果区域区分成功、失败、警告三种语义色。
- API Key 增加显示/隐藏切换，但不要默认明文展示。

验收标准：

- 移动端首屏可以看到主要配置入口。
- 无效 Base URL 有字段级错误提示。
- 测试连接失败时给出原因和下一步，例如“检查 baseUrl 是否包含 /v1”。

### P6：补齐可访问性与键盘体验

可访问性 (Accessibility, a11y) 是让键盘用户、屏幕阅读器用户、低视力用户也能完成同样任务的设计和工程要求。

建议：

1. 所有交互元素保留可见焦点环，不要只依赖 hover。
2. 当前导航项使用 `aria-current="page"`。
3. 筛选按钮使用 `aria-pressed` 表达选中状态。
4. 表单错误使用 `aria-describedby` 关联字段和错误文本。
5. 测试连接结果使用 `aria-live="polite"`，让屏幕阅读器能听到异步结果。
6. 颜色状态同时配文字，不只靠颜色。

验收标准：

- 只用键盘 Tab 可以从导航走到主操作、筛选、列表和详情入口。
- 焦点顺序和视觉顺序一致。
- 禁用按钮有 `disabled` 属性，并且视觉上明显不可用。

### P7：加入少量有意义的动效

目标：不做装饰性动画，只为状态变化提供反馈。

微交互 (Micro-interaction) 是按钮按下、筛选切换、表单提交等小范围反馈。它能让界面感觉更可靠，但不应拖慢操作。

建议：

- 按钮按下：80-150ms 内有轻微颜色或阴影变化。
- 筛选展开/收起：150-200ms 高度或透明度过渡，但避免动画影响布局稳定。
- 卡片 hover：桌面端轻微改变背景，不移动卡片位置。
- 支持 `prefers-reduced-motion`，用户系统开启减少动态效果时关闭非必要动画。

验收标准：

- 动效不超过 300ms。
- 动效不造成布局跳动。
- 开启减少动态效果后仍可正常使用。

## 建议任务拆分

### Sprint 1：移动端修复

- 修复移动端导航裁切。
- 修复卡片和主面板横向溢出。
- 给 NoteCard 摘要改为 line-clamp。
- 给详情入口和导航项补足触控面积。

预期收益：设计评分从 C+ 提升到 B-，响应式从 D+ 提升到 B-。

### Sprint 2：视觉系统收敛

- 拆分颜色语义令牌。
- 建立阴影三档。
- 降低普通卡片视觉重量。
- 缩小二级页标题。

预期收益：视觉疲劳下降，页面层级更清楚。

### Sprint 3：工作流优化

- 任务筛选移动端折叠。
- AI 配置页配置优先。
- 表单字段级错误和异步反馈。
- 导航、筛选、表单补齐可访问性属性。

预期收益：用户好感度从 56/100 提升到 70+。

- [x] 当前页、当前筛选、按钮禁用态都有明确视觉和语义状态。
- [x] 所有触控目标不低于 44x44px。

## 不建议现在做的事

1. 不建议引入新的 UI 组件库。当前项目已有清晰自定义视觉语言，引入组件库会带来风格冲突。
2. 不建议大改品牌风格。纸质工作台方向是项目少数明确优点，应先减重而不是推倒。
3. 不建议先做暗色模式。当前浅色模式的令牌和层级还没稳定，暗色模式会放大维护成本。
4. 不建议把所有筛选都改成图标。当前对象多为文字概念，图标会增加理解成本。
5. 不建议用更多装饰图形解决空白。工具型产品应该靠信息结构和状态反馈建立质感。
